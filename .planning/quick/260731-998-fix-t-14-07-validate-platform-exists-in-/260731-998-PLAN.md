# Quick Task 260731-998: Fix T-14-07 platform-existence 500 leak

## Problem

`backend/writes.py:apply_add_portfolio_event` never checks that `after["platform_id"]`
references an existing `Platform`. A nonexistent `platform_id` reaches the FK and
raises `IntegrityError` on commit, surfacing as a **500 stack-trace leak** on the three
Phase-14 REST routes that funnel through this function:
`POST /portfolio-events/funded-buy`, `/funded-sell`, and `/investment-transfer`
(the transfer's deposit leg calls `apply_add_portfolio_event` internally).

Confirmed empirically by the Phase-14 security auditor via in-process `TestClient`
probe: bad `platform_id` → 500, not the promised 422. Threat T-14-07 (Information
Disclosure, medium) in `.planning/phases/14-rest-endpoints-agent-mcp-tool-registration/14-SECURITY.md`.

## Fix (root cause, one chokepoint)

`apply_add_portfolio_event` is the single function every affected caller routes
through (3 REST routes + agent dispatch + the inherited Phase-13 `create_portfolio_event`
route). Add one existence guard at the top of the function body (before the
`existing_holding` query, ~`backend/writes.py:434`):

```python
if db.get(Platform, after["platform_id"]) is None:
    raise ValueError(f"platform {after['platform_id']} not found")
```

- `Platform` is already imported (`backend/writes.py:23`).
- `db.get(Platform, ...)` idiom already used at `writes.py:345,402`.
- `ValueError` is already mapped to `HTTPException(422)` by every caller — no handler
  changes needed. This converts the 500 into a clean 422 everywhere at once.

## Task
