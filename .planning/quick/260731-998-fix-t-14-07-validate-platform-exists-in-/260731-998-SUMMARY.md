# Quick Task 260731-998: Fix T-14-07 platform-existence 500 leak — Summary

One-liner: added a `db.get(Platform, ...)` existence guard at the top of
`apply_add_portfolio_event` so a nonexistent `platform_id` raises `ValueError`
(→ 422) instead of falling through to an `IntegrityError` (→ 500) at commit.

## What changed

- `backend/writes.py` — `apply_add_portfolio_event` now checks
  `db.get(Platform, after["platform_id"]) is None` before doing anything
  else, raising `ValueError(f"platform {after['platform_id']} not found")`.
  This is the single chokepoint every affected caller (3 REST routes:
  funded-buy, funded-sell, investment-transfer's deposit leg; plus agent
  dispatch) routes through, so the fix closes T-14-07 everywhere at once
  with no handler changes (`ValueError` → `HTTPException(422)` mapping
  already existed in `main.py`).
- `backend/tests/test_write_endpoints.py` — added
  `test_funded_buy_rejects_nonexistent_platform`, asserting
  `POST /portfolio-events/funded-buy` with `platform_id=999999999` returns
  422, not 500. Follows the file's existing idiom (`zz14test-` prefix,
  `require_api_key` header, `finally`-block account cleanup — no platform
  cleanup needed since none was created, and no transaction/portfolio-event
  cleanup needed since the route never commits on the `ValueError` path).
