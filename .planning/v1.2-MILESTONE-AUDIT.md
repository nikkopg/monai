## Cross-Phase Integration (from gsd-integration-checker)

All six audited areas **VERIFIED**, no broken seams, no blockers:

1. **Money-movement chain** (P13→P14→P16/17): 5/5 `apply_*` have a REST route + a confirm-dispatch branch + a dual-registered `propose_*`. No backend/chat dead ends.
2. **Transfer-pair atomicity** (XFER-01, REC-05): `transfer_pair_id` written by `apply_add_transfer`, single-leg guard enforced backend (`writes.py:117-143`) and UI; Records collapses pairs and deletes as a unit; bulk-delete pulls the sibling leg.
3. **Double-count prevention** (ACCT-03, NW-01): `cashflow_transactions` view excludes investment accounts; `net_worth()` counts liquid accounts + investment platforms once each and asserts 100% account coverage (raises on any unclassified row).
4. **Category hierarchy consumption** (CAT-01/04): `resolve_category_id` dual-writes on create/edit/bulk-recategorize; filters/modal use the hierarchical picker with descendant rollup.
5. **MCP read-only boundary** (CHAT-09): `READ_TOOL_NAMES` snapshot taken before write tools merged; MCP surface iterates only reads — write tools cannot leak.
6. **Frontend→backend contract**: UI fetch calls match existing routes/shapes for every flow the UI exercises.

**Integration WARNING (not a blocker):** `apply_add_investment_transfer`, `apply_add_funded_buy/_sell`, and `apply_add_balance_adjustment` (ACCT-02, XFER-02, XFER-03) have REST routes and agent tools but **zero UI caller** — reachable only via chat or direct API.
