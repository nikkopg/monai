## Spacing Scale

Declared values — **these are the project's existing tokens** (`ui/app/styles.ts:62-68`), not the generic 8-point scale. Phase 15 reuses them as-is; do not introduce new spacing values.

| Token | Value | Usage |
|-------|-------|-------|
| `tokens.space.xs` | 6px | Icon-to-text gaps, chip internal padding |
| `tokens.space.sm` | 8px | Compact inline gaps (delta chip, badges) |

## Layout Contract (prescriptive — the actual UI change)

Three regions on the existing `/cashflow` page, top to bottom. Everything below reuses an existing card/grid pattern already on this page; none of it is a new visual language.

### 1. Hero row (existing 2-col grid, `page.tsx:274-416` — MODIFY card A only)
- Card A ("Net worth", ink dark hero): keep exact visual treatment (background `tokens.color.ink`, radius 18, padding `26px 28px`, serif 52px number, `tabular-nums`). **Change:** the number now sources from `GET /net-worth`'s combined total, not the client-side `reduce` over all accounts (the fixed double-count bug). **Remove the ▲/▼ delta chip** (`page.tsx:316-348`) — the backend's net-worth read is a point-in-time snapshot (liquid derived-balance + investment `portfolio_summary.total_value`), and there is no locked NW-01/NW-02 requirement for a period delta on the combined number (net-worth trend is explicitly deferred, see CONTEXT.md `<deferred>`). Do not invent one.
- Card B (6-month trend): unchanged, out of scope.

### 2. Split row (NEW — insert directly below the hero row, above the existing "Stat cards" row)
- Grid: identical shape to the existing "Stat cards" row (`page.tsx:419-446`) — `repeat(auto-fit, minmax(min(100%, 200px), 1fr))`, `gap: 18`.
- Two cards, each reusing `statCard`/`statLabel`/`statValue` exactly (`page.tsx:754-769`: white bg, border, radius 16, padding `20px 22px`; label 13px muted; value 28px/600 tabular-nums, color `tokens.color.ink` — neutral, not green, since these are totals not deltas).
  - Card A: label "Liquid", value = liquid total (money-formatted), one small muted (13px) subtext line below the value: "{N} accounts".
  - Card B: label "Investment", value = investment total (money-formatted), subtext "{N} platforms".

### 3. Breakdown row (MODIFY the existing "Category + accounts" 2-col grid, `page.tsx:448-577`)
- Grid shape unchanged: `repeat(auto-fit, minmax(min(100%, 300px), 1fr))`, `gap: 18`.
- Left card stays "Spending by category" — untouched, out of scope.
- Right card: rename "Accounts" → **"Liquid accounts"**, and filter its rows to `type === 'liquid'` only (using the extended `account_balances` payload's new `type` field). Row markup is byte-identical to the existing pattern (`page.tsx:515-575`: initials avatar, name, balance, `period_net` delta) — just filtered.
- **NEW third card** (this row becomes a 3-up grid once the investment card is added — the existing `auto-fit minmax(300px)` grid handles this responsively with no manual breakpoint math): **"Investment platforms"**, one row per `portfolio_summary.groups` entry:
  - Reuse the exact row shell (icon-badge + name + right-aligned value, `padding: "11px 0"`, `borderTop: 1px solid tokens.color.borderInner`).
  - Left: a `34×34` badge (same size/radius/background as the account-initials avatar) showing the platform's initials (same `initials()` helper) instead of a new icon.
  - Center: platform name (14px/500, matching account-name weight).
  - Right: subtotal value only (14px/600, tabular-nums, neutral `ink` color — **no delta/PnL line**, since `portfolio_summary.groups` carries no period-net equivalent and inventing one is out of scope for NW-01/NW-02).

### Responsive / empty behavior
- If liquid accounts list is empty: render the "No liquid accounts yet." empty state (copy above) in place of the row list, matching the existing "No transactions yet." empty-state visual pattern (`page.tsx:607-616`: 16px/600 heading + 14px muted body, no border).
- If investment platforms list is empty: same treatment with the investment empty copy.
- The whole breakdown row (like the existing "Category + accounts" row) only renders when `hasActivity` is true today — **extend this gate** so the breakdown row still renders whenever there is at least one liquid account OR one investment platform, even with zero cashflow activity this period (net worth is not period-scoped the way spending/income are — an account with a balance but no transactions this month must still show).
