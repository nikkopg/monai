## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Next.js proxy | Untrusted form input (source_account_name, quantity, price, cash_amount) crosses here; the proxy injects MONAI_API_KEY server-side |
| Next.js proxy → FastAPI | `require_api_key`-gated write; FastAPI resolves the account by name and writes the portfolio event + cash leg in one DB transaction |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-03-T | Tampering (data integrity) | `source_account_name` resolution via `_get_or_create_account` | medium | mitigate | The "Funding account" field is a `<select>` populated from a fresh `GET /accounts` fetch, client-filtered to `type === "liquid"`, submitting the exact existing account name. No free-text account input — a mismatching name would silently fork a duplicate account (RESEARCH Pitfall 2). The e2e asserts the field is a `<select>` and the submitted name matches a mocked account. |
| T-18-03-C | Tampering | Client-side cash_amount default (quantity × price) and preview | low | accept | `cash_amount` is sent as an explicit field the backend treats as authoritative-as-received under Pydantic `gt=0`; the quantity × price default is a UX convenience, deliberately independent of quantity/price server-side (fees/rounding). Preview is presentation-only. |
| T-18-03-I | Information Disclosure | API key exposure | low | mitigate | Submit only through the `/api/...` Next.js proxy. Never reference `MONAI_API_KEY`, a `NEXT_PUBLIC_` var, or the raw backend URL from the client component. |
| T-18-03-E | Elevation of Privilege | Write reachable off the web app | low | mitigate | funded-buy/funded-sell stay web-app-only, API-key-gated REST writes; this plan adds no agent/MCP tool and does not touch `READ_TOOL_NAMES` (stays 15). |

No package installs occur in this plan — T-18-SC (supply-chain) is not applicable. No high-severity threats identified.
</threat_model>
