<objective>
Add `apply_add_balance_adjustment` to `backend/writes.py`: setting an account's balance
writes a single "Adjustment"-tagged `Transaction` whose amount is
`target − current_derived_balance`, where the derived balance is a FRESH, UNFILTERED
`SUM(amount)` over all the account's transactions (transfers included). Closes ACCT-02
and SC #4.

Purpose: This is the function RESEARCH's blocking Finding 2 is about. The one existing
"balance" query (`tools.py:account_balances`) deliberately EXCLUDES transfer rows and is
the WRONG basis for the delta — reusing it would produce a delta off by the account's
entire transfer volume (proven live: account 1 has a +60.6M transfer sum vs a −61.4M
non-transfer sum). The adjustment must reconcile against the account's actual cash
position. The account balance itself stays derived — the adjustment row is the only thing
written (D-07). It is tagged so it affects the derived balance but not cashflow totals
(D-08). Never commits (D-01).
Output: `backend/writes.py` gains one function; plan 01's adjustment-delta and
cashflow-exclusion tests go GREEN.
</objective>
