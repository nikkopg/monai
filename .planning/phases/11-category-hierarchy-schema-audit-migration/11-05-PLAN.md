<objective>
Close the write-path gap: after the migration, `category_id` exists on every historic
row, but new inserts would still leave it NULL. Implement D-08 dual-write on every
transaction write path — direct REST (POST /transactions, PUT), agent writes
(apply_add/edit_transaction), and CSV import — with the D-04 Uncategorized fallback
so no NULL category can ever be created (Pitfall 2: resolve in app code, never lean
on a DB rejection).

Purpose: this is what makes the D-04 "no NULL categories remain" claim durable
rather than a one-time migration fact.
Output: all insert paths hierarchy-aware; legacy `category` string still written
(dual-write until the later drop migration); `raw_category` untouched forever.
</objective>
