# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** Per RESEARCH.md's Architectural Responsibility Map, the full category-picker
> *component* build is Phase 16/17 work — this phase only needs the data source hierarchy-shaped.
> This contract is written now anyway (D-15/D-16 are locked) so Phase 16/17 have zero design
> ambiguity later, and so the Settings tree manager and CategoryDonut — which DO ship this phase —
> have one. No new dependency, no new design system: everything below is the existing `ui/app/styles.ts`
> "paper" token layer applied to three surfaces.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no shadcn, no CSS framework (project convention, confirmed: no `components.json` anywhere in repo) |

existing `tokens.*` entry or a same-family derived swatch for the category color palette (D-14),
called out explicitly as new.

## Spacing Scale

This project's existing scale (`tokens.space` in `ui/app/styles.ts`) is **not** 4-multiples — it's
an already-shipped, deliberately tighter scale used across every existing page (Cashflow, Settings,
Investments). Reuse it as-is; do not introduce a parallel 8-point scale for this phase's new tree/picker UI.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 6px | Icon-to-label gap (emoji ↔ category name), badge inner padding |
| sm | 8px | Row internal gaps, button icon gaps |
| md | 14px | Default row/field spacing, card horizontal rhythm |
| lg | 18px | Section spacing inside a card, card padding component |
| xl | 24px | Card bottom margin, page-section breaks |

Exceptions:
- **Tree indentation per hierarchy level: 20px.** New value, not in `tokens.space` — needed for the
  expandable tree's visual nesting (D-16). Level 1 (top group) = 0px indent, Level 2 = 20px, Level 3
  (max depth per CAT-01) = 40px. Chosen as a round value distinct from the 14/18 rhythm so nesting
  reads unambiguously at a glance without competing with the existing spacing tokens.
- Row height in the tree and picker: 36px min-height (touch-comfortable for inline add/edit/delete
  icon-only actions), consistent with existing `AccountManager`/`CategoryManager` table row padding
  (`8px 4px` cell padding ≈ 34–36px effective row height).

## Typography

Reusing the existing four-size rhythm already established across `CategoryManager.tsx`,
`AccountManager.tsx`, and `settings/page.tsx` — no new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / row text (tree rows, picker rows, table cells) | 13px | 400 | 1.5 |
| Label / meta (badges, counts, group headers in picker) | 12px | 400 | 1.5 |
| Interactive / form (inputs, buttons, dialog message) | 14px | 400 (600 on primary buttons) | 1.5 |
| Empty-state heading | 20px | 600 | 1.2 |

Weights: exactly 2 — **400 regular** (body, labels, dialog copy) and **600 semibold** (primary
button text, card titles, empty-state heading, active/selected tree node name). The existing `500`
used only on the Settings page's inactive segmented-control tab is pre-existing page chrome, not
introduced by this phase, and does not apply to any Phase 11 surface.

Card titles reuse the existing `cardTitle` pattern (15px/600) from `settings/page.tsx` unchanged —
the Settings > Categories section header ("Categories") sits in that same style, not a new size.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ece8e1` (page) / `#f7f5f1` (panel) | App background, centered Settings panel behind all cards |
| Secondary (30%) | `#fff` (card), `#f2efe8` (sidebar), `#faf8f4` (inputBg) | Category tree card surface, tree row background, search input in the picker |
| Accent (10%) | `#2f6f4f` (green) | Reserved for: primary CTA buttons ("Add category", "Save category"), the selected/active row indicator in the tree, focus ring on the picker's search input. NOT used for category swatches — see Category Color Palette below, which is a distinct system per D-14. |
| Destructive | `#b5503f` (terracotta) | Delete-category action label, `dangerBtn` (confirm-delete/confirm-merge buttons), error text |

Accent reserved for: primary "Add category" / "Save category" buttons, the tree's
currently-selected/expanded-and-focused row highlight, and the picker search input's focus border.
Never used for decorative fills, card backgrounds, or as a category swatch color.

### Category Color Palette (D-14)

A curated 13-swatch palette derived from the existing token layer — 7 direct reuses of tokens
already in `ui/app/styles.ts`, 4 new same-family tints (kept within the paper aesthetic's warm/muted
range; no saturated/bright colors introduced), assigned one-per-BudgetBakers-top-group plus 2 system
swatches. Subcategories inherit the parent's swatch by default; the tree/edit form exposes an
override picker limited to this SAME 13-swatch set — no second, larger palette (ponytail: one
palette, not two).

| Top-level group | Swatch | Source |
|---|---|---|
| Food & Drinks | `#d8b26a` | existing `tokens.color.gold` |
| Shopping | `#b5503f` | existing `tokens.color.terracotta` |
| Housing | `#5a8f73` | existing `tokens.color.sage` |
| Transportation | `#8fae9c` | existing `tokens.color.sageLight` |
| Vehicle | `#a8674a` | new — dusty rust, between terracotta/gold |
| Life & Entertainment | `#8a6a8f` | new — muted plum |
| Communication / PC | `#6b7f8f` | new — muted slate-blue |
| Financial Expenses | `#6f6857` | existing `tokens.color.muted3` |
| Investments | `#c9973f` | new — deep ochre (distinct from Food's gold) |
| Income | `#23543c` | existing `tokens.color.greenDark` |
| Others | `#c8c1b5` | existing (6th `chartColors` entry) |
| **Transfer** (system) | `#a49c8c` | existing `tokens.color.muted2` — deliberately neutral; excluded from spending charts (D-12) |
| **Uncategorized** (system) | `#8b8474` | existing `tokens.color.muted` — deliberately neutral, signals "needs attention" |

Subcategory swatches inherit their parent's hex by default (D-14); an override sets a different swatch
from this same 13-value set — never a freeform color picker (keeps the palette closed and legible in
charts).

**Icon/swatch chip convention:** every place an emoji is shown next to a category name (tree row,
picker row, donut legend), render it inside a small circular chip whose background is the category's
swatch color **at 16% opacity** — reusing the exact opacity already established by
`tokens.color.chipGreenBg` (`rgba(129,196,158,.16)`), not inventing a new opacity value. The emoji
itself renders at full color/no filter on top of the tinted chip.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Add category" (tree manager, top-level or in-context "Add subcategory" when adding under a selected node) |
| Empty state heading | "No categories yet." |
| Empty state body | "Categories are created automatically during setup, or add your first one below." (Migration seeds ~11 groups + Transfer + Uncategorized, so this state is effectively fresh-install-only, not the live-data path — copy still needs to exist for that path.) |
| Error state | "Couldn't {rename/merge/delete/add/edit} category: {detail}. Nothing was changed." — reuses the exact `extractDetail()` error-copy pattern already in `CategoryManager.tsx`/`AccountManager.tsx`; do not invent a new error phrasing convention for this phase. |
| Destructive confirmation — delete, no records/children | "Delete this category? This can't be undone." (plain `ConfirmDialog`, matches `AccountManager`'s account-delete copy) |
| Destructive confirmation — delete, blocked (records and/or subcategories exist) | "{N} transactions and {M} subcategories use this category — choose where to reassign them, or cancel." (extends the existing reassign-picker copy pattern from `AccountManager.tsx` to cover Pitfall 3's dual transaction+subcategory case; omit whichever count is zero, e.g. just "{N} transactions use this category — choose a destination category to reassign them, or cancel." when there are no child categories) |
| Destructive confirmation — merge (existing, retained per D-11) | `Merge "{from}" into "{into}"? {affectedCount} transactions will be updated. This can't be undone.` (unchanged from current `CategoryManager.tsx`) |
| System-category lock | "System category — can't be deleted." (tooltip/inline note on Transfer and Uncategorized rows; their delete action renders disabled/grayed, not hidden, so the reason is visible) |
| Migration mapping review pause (D-06 execution checkpoint, not a persistent UI string but the executor's chat-facing copy) | Present the drafted mapping and ask the user to review/edit before the migration runs — no fixed microcopy contract needed here since it's a conversational checkpoint, not a UI surface. |

## Component Inventory & Interaction States

### 1. Settings > Categories — expandable tree manager (D-16)

Moves `CategoryManager.tsx` from `ui/app/cashflow/` to `ui/app/settings/`, replacing its current flat
rename/merge table with a tree. Built as a plain recursive component (per RESEARCH.md's "Don't
Hand-Roll" table — no tree-view library; ~11 top nodes × a handful of children is trivial with local
`useState`).

- **Structure:** top-level groups render as rows with an expand/collapse chevron, **collapsed by
  default** (per D-16). Expanding reveals subcategories indented 20px; a 3rd level (if present) indents
  a further 20px (40px total). Depth is capped at 3 (CAT-01) — the "Add subcategory" action is hidden/
  disabled on any row already at depth 3.
- **Per-row content, left to right:** expand chevron (top-level/parent rows only) → emoji chip (16%-
  opacity swatch background, per Color section) → category name (13px/400, 600 on hover-focus) →
  transaction-count badge (reuse existing `badgeStyle` pattern: 12px, `tokens.color.muted`, pill
  background `tokens.color.border`) → inline actions (Add subcategory / Edit / Delete), right-aligned,
  visible on row hover only (matches existing `CategoryManager`/`AccountManager` hover-reveal pattern
  for Rename/Merge).
- **Inline add/edit:** clicking "Add subcategory" or "Edit" swaps the row's name cell for an `input`
  (existing token style) plus a swatch picker (13-color palette, small circular swatch buttons) and an
  emoji text field — mirrors the existing inline-edit pattern in `AccountManager.tsx` (input + Save +
  Cancel inline, no modal for non-destructive edits).
- **Delete guard (CAT-02, Pitfall 3):** clicking Delete on a row with 0 direct transactions AND 0 child
  categories → plain `ConfirmDialog`. Clicking Delete on a row with transactions and/or subcategories →
  reassign-flow `ConfirmDialog` with a destination-category `<select>` injected via the dialog's
  `children` slot (existing `ConfirmDialog` component already supports this — see
  `AccountManager.tsx`'s reassign branch). The reassign target list excludes the category being deleted
  and its own descendants (can't reassign into a subtree being removed).
- **System rows (Transfer, Uncategorized):** rendered identically but with the Delete action disabled/
  grayed and a small lock affordance; Edit is still allowed for color/icon but name/parent are locked
  (Transfer and Uncategorized are structural, not user-renamable — Claude's-discretion call, consistent
  with them being system rows per D-04).
- **States:** default, row-hover (reveals actions), expanded/collapsed (chevron rotation), inline-
  editing (input replaces static text), error (inline red text below the tree, same pattern as existing
  `CategoryManager.tsx`'s `error` state), loading (initial fetch — reuse existing empty-until-loaded
  pattern, no skeleton needed at ~100 rows).

### 2. Searchable grouped category picker (D-15)

Design contract only this phase (component consumed by record forms/filters, built in Phase 16/17 per
RESEARCH.md scope note) — defined now so those phases implement against a fixed spec.

- **Trigger:** a button/field styled like `input` showing the currently-selected category's emoji chip
  + name (or a placeholder like "Select category" in `tokens.color.muted`).
- **Popover/dropdown body:** opens below the trigger, `card`-token surface (white, `border` token,
  `radius.md`), max-height with internal scroll (~320px), a search `input` pinned at the top
  (type-to-filter, filters by name substring across all levels, case-insensitive).
- **List layout:** top-group names render as non-selectable section headers (12px, `muted2`, uppercase
  tracking — matching the existing "Configuration" eyebrow-label style in `settings/page.tsx`);
  children render as selectable rows indented 20px under their header, each with the emoji chip + name.
  Any-level assignment (D-01) means a top-group row itself is ALSO selectable, not just a header —
  render it as both a header label and a clickable row (bold/600 weight) so a parent-only assignment
  reads as intentional, not a mistake.
- **Type filtering:** the picker is instantiated per record-type context — an Income form instance only
  ever receives/shows income-typed top groups and their children (D-03); this is a data-filtering
  contract (the picker's data source is pre-filtered server-side or by prop), not a visual toggle inside
  the picker itself.
- **Selected state:** selected row shows a checkmark or accent-colored left border (`tokens.color.green`,
  2px) — small, not a filled background (keeps the muted palette from looking noisy with 13 swatch
  colors already in play).
- **Empty search result:** "No matching categories." in `muted` 13px, centered in the popover body.

### 3. CategoryDonut — top-level rollup + drill-down (D-09)

Extends the existing `CategoryDonut.tsx` (currently a flat 150×150px ring cycling 6 `chartColors`).

- **Default view:** ring shows the ~11 top-level groups (plus Others/Transfer-excluded per D-12), each
  slice colored by that group's palette swatch (not the old `chartColors` cycle — swatches are now
  1:1 with category identity, so the same group is always the same color everywhere in the app).
- **Drill-down interaction:** clicking a slice re-renders the same 150×150px ring scoped to that group's
  subcategories (same swatch family, e.g. tints if needed — but per the "one palette" rule, subcategories
  reuse the PARENT's exact swatch since D-14 says subcategories inherit color by default; the drilled-in
  ring will render monochrome-ish by design unless a subcategory has been individually recolored — this
  is expected, not a bug).
- **Back affordance:** a small "‹ Back" text link (12px, `muted2`) appears above/beside the donut only
  in drilled-in state; clicking it returns to the top-level rollup. No breadcrumb trail needed since
  depth is capped at "top group → subcategories," never deeper in this chart.
- **Tooltip:** unchanged existing pattern (`card` background, `border2` border, 12px text).
- **Transfer exclusion (D-12):** the Transfer system category never appears as a slice in this chart at
  either level — it's filtered out of the query, not rendered-and-hidden.
